# AZZAMS 1.13 — approved interface redesign

Desktop and admin Android share the new white/ivory/burgundy design system with Cairo typography. Operational home, analytics, monthly close and close-history now have separate routes. Analytics offers custom dates, period comparisons, sales/profit/campaign views, SVG trend, detailed breakdowns and full CSV export. Monthly closing exposes live/frozen period selection, statement, separate courier balances, review drilldowns, scheduling controls, CSV/JSON exports and previous archives. Open periods are not mislabeled as approved; automatic closing retains the 1.12 engine.

Home keeps search, pagination, order details and printing. Desktop adds selected-only bulk status/printing using the existing transition guards. Mobile preserves single/bulk status and printing and gets an Accounts navigation entry. All original static IDs and entry points are retained. Existing legacy reports/tools remain accessible on an additional-tools route. The packing route reconnects existing packing functions to a usable screen. Shared v6 helpers required by the existing settlements and packing screens are now exposed.

No production records were changed by this release. Accounting/inventory mutations remain in existing services. The 1.12 deployment blockers still apply: the Firebase scheduler has not been deployed, and the original Android signing key is not available, so CI debug APKs cannot be assumed to install over previously signed versions.

Checks: all original HTML IDs retained; shared financial tests; browser fixtures for actual edit/concurrency, advertising single expense, monthly snapshots and no deletion, closed expense lock; all admin routes; desktop selected-only bulk transition; responsive layouts; original paired thermal/gift printing, escaping and overflow guard, notification read state, mobile single/bulk transitions. Browser tests are simulated Firebase, not production or physical Android-device tests.
